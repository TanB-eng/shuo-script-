README 设计
目标
为仓库根目录编写一份面向首次使用者的中文 README.md，让读者能够从 GitHub 下载项目、安装依赖、按当前推荐方式启动脚本，并准确了解现阶段已经实现的功能、限制和安全注意事项。

读者与写作方式
主要读者是使用 Windows、但不熟悉 Node.js 项目的普通用户。
采用一页式结构，先给出最短可执行步骤，再补充功能、配置和排错信息。
所有命令均可直接复制；不假定读者理解 WebSocket、用户脚本或本地桥接。
只描述代码当前已经实现的能力，不把规划或未经验证的能力写成可用功能。
README 结构
项目名称和一句话简介。
当前状态提示：推荐浏览器桥接模式；Node 直连模式可能被边缘层返回 502。
功能列表。
环境要求：Windows、Node.js 18 或更高版本、现代 Chromium 浏览器。
下载方式：GitHub ZIP 和 git clone。
安装依赖：npm install。
推荐启动步骤：
双击 启动bot.bat，或运行 npm run bridge。
打开并登录游戏页面。
在开发者工具控制台执行 游戏控制台启动代码.txt 中的一行加载命令。
保持 Node 窗口和游戏标签页可见。
观察模式：npm run bridge:observe。
停止方式：终端按 Ctrl+C。
本地配置 config.json 的示例和说明。
常见问题：桥接未连接、浏览器后台节流、直连 502、授权及凭据。
安全与责任说明。
当前功能描述
README 将以当前代码为准说明：

满血后才开始寻找金币。
自动选择较近且附近玩家风险较低的金币。
保留一部分 1 小时体力，避免拾金耗尽逃生能力。
不主动攻击；检测到掉血并识别攻击者后才反击。
当前默认在 HP 低于 90 且正在受攻击时逃生。
有安全传送坐标且体力足够时优先传送，否则离开可见实体层。
当前默认离线冷却 90 秒，之后重新加入并等待满血。
支持只观察、不发送游戏动作的桥接观察模式。
启动方式取舍
README 把浏览器桥接作为唯一推荐方式。npm start 的 Node 直连模式保留为开发/诊断入口，并明确说明它可能因为边缘层对非浏览器 WebSocket 的处理而得到 502，普通用户不应把它作为首选启动方式。

配置与敏感信息
本地配置文件为根目录 config.json，不提交到 Git。
README 提供最小示例，只展示 escapeHp、offlineCooldownSec 和 safeTeleport。
会话 token、Cookie、授权回调 URL 和 .data 运行状态不得写入 README、截图或提交历史。
验证标准
README 中的仓库地址、文件名和 npm 命令与当前仓库一致。
推荐启动步骤能从空白下载目录执行到桥接等待状态。
功能说明与当前代码默认值一致，特别是 90 HP / 90 秒。
明确区分推荐桥接模式和存在 502 风险的直连模式。
README 不包含 token、Cookie、用户 ID 或其他私人会话信息。
