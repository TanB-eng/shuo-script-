# 拾金与逃生行为修正设计

## 目标

修正浏览器桥接 Bot 的两个决策行为：拾金只以生命值是否满血为准，不再受 1h 体力保护线阻止；低于逃生血量且受到攻击时优先传送，传送不可用或失败时下线，传送成功后只根据落地后的新受击事件决定是否继续逃生。

## 行为规则

### 拾金

- 未满血时停止移动并原地回血。
- 满血后允许选择和追踪金币。
- 1h 体力剩余量不再作为拾金开关。
- 服务器自身的体力限制仍然有效；本次只删除 Bot 的额外 1800 点保护线。

### 低血逃生

- 只有 `HP < escapeHp` 且最近发生新的受击事件时才进入逃生。
- 可以传送时优先传送。
- 传送体力不足、没有可用目标、发送失败、服务器拒绝或超时时执行下线冷却。
- 传送成功后进入等待满血状态，并清除传送前的受击历史。
- 落地后没有新受击事件时，即使 HP 仍低于阈值，也原地回血，不继续传送或下线。
- 落地后再次掉血时，该新事件可以重新触发逃生。

## 修改范围

- `src/bot-bridge.js`：删除拾金前的体力保护分支；传送成功后清除旧受击历史。
- `src/state.js`：提供清除受击历史的明确方法。
- `src/strategy.js`：提供可测试的拾金资格判断，规则仅为满血。
- `test/behavior.test.js`：覆盖低体力满血仍可拾金、未满血不可拾金、传送后旧受击不再触发逃生、新受击可以再次触发逃生。

## 完成标准

- 满血且 1h 体力低于 1800 点时仍进入拾金逻辑。
- 未满血且无人攻击时只原地回血。
- 传送前的掉血记录不会在落地后重复触发逃生。
- 落地后的新掉血记录仍能触发逃生。
- 传送不可用或失败时保留现有下线回退行为。
- 使用 Node 内置测试运行器执行新增测试，并让桥接相关源码通过语法检查。
